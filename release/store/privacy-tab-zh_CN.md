## 单一用途说明 · `07-single-purpose.txt`

TabPocket 只做一件事：给用户一个本地的地方，记住他自己的浏览器里还开着的标签、他选择留下的书签，以及这些页面占了多少时间。

扩展里的每一处都在服务这一件事。一个会话，是用户选择留下的那批标签；一个收藏，是用户选择留下的那个页面；统计页算的是这些页面在前台待了多久；收藏体检则是把用户已经收藏过的页面按打开次数排个序。它们不是捆在一起的几个独立产品，而是同一份「用户自己浏览记录」的四个视图 —— 而这份记录从不离开浏览器。没有第二个目的，没有账号，没有服务器，没有统计上报。

## 权限理由 · 8 个框

### `tabs` · `08-permission-tabs.txt`

用来读出用户选择留下的那些标签的标题和网址。用户点「收拢全部标签」时，扩展读取这些标签、写进本地会话；点「恢复」时再用 `chrome.tabs.create` 把它们打开。同一次读取也让计时器知道当前前台是哪一个网址。

范围只限用户自己的窗口。标题和网址只写进本地会话记录，别的什么都不做：不上传、不分析、不拿去和服务端比对。扩展也不会定时轮询标签。

没有更窄的权限可用。`activeTab` 只在用户手势后覆盖单个标签，无法整窗收拢或恢复；`tabs` 才是按窗口级保存会话的前提。

### `storage` · `08-permission-storage.txt`

`chrome.storage.local` 存用户的会话、收藏、设置和语言选择，这样弹窗和后台 service worker 读到的是同一份状态，浏览器重启后也还在。

`storage.session` 只放一个有易失性的值：计时器当前的起算点，浏览器关闭就该丢。不写 `storage.sync`，没有任何服务端存储。

没有更窄的权限能覆盖这些数据：它们必须活过浏览器重启（这排除了 `storage.session`），又必须在弹窗首屏绘制前就读到（这让 IndexedDB 不适合放几个小配置 —— 它已经用来存体量大得多的访问记录）。

### `alarms` · `08-permission-alarms.txt`

MV3 的 service worker 空闲约 30 秒就被终止，内存里的计时器无法自行存活。一个短周期的重复 alarm（默认一分钟，用户可调到 30 秒）把 worker 唤醒，结算当前页面在前台停留了多久，然后继续停着。

这是扩展里唯一的周期任务。它只创建一次，已存在就复用，不发任何网络请求，用户暂停统计或卸载时会被清除。

没有它，两次 worker 挂起之间累积的前台时间会直接丢失，统计页就会不准。

### `contextMenus` · `08-permission-contextMenus.txt`

只加一个右键菜单项「把这个页面加进 TabPocket」，让用户不必先打开弹窗就能存页面。

点击之后只做一件事：把当前标签的标题和网址写进本地收藏列表。没有子菜单，没有动态项或按站点生成的项，不读选中文字，也不接触页面内容。

### `unlimitedStorage` · `08-permission-unlimitedStorage.txt`

长期统计会按「每个访问过的页面每天一条」累积，且不自动清理，扩展自己的存储会一直长下去。

`unlimitedStorage` 让扩展所在的源不受浏览器存储配额限制，这样在用了几个月之后，不会因为配额错误让统计悄悄停掉。没有它，扩展就只能删除用户更早的历史数据来腾地方。

这个权限不给用户文件的访问权，不给页面内容的访问权，也不增加任何网络能力。它只是取消扩展自有数据的配额上限。

### `bookmarks` · `08-permission-bookmarks.txt`

只被两个由用户主动触发的功能使用：「整理收藏」与「收藏体检」。

整理会读取已有的书签树，让用户在并入 TabPocket 自己的列表之前先看清已经存了什么。体检把同一棵树摊平成一张表，好让用户给收藏排序。写入（新建/删除单个书签）只在这两个界面里点击之后发生；后台什么都不做。

书签不离开设备，也不发往任何服务器。没有更窄的权限：用户的真实书签树正是这个权限提供的东西，没有别的 API 能读到。

### `history` · `08-permission-history.txt`

只被书签相关的视图使用，而这些视图的全部价值就是「你存的这个页面到底打开过几次」。

收藏列表按**累计**访问次数排序：一次 `chrome.history.search` 在内存里建一张网址到次数的映射，短时间内复用。收藏体检要的是**某段时间内**（30/90/365 天）的次数，而 `history.search` 只给累计值，所以体检对每个书签网址调 `getVisits`，再按 `visitTime` 在本机过滤。

严格只读：从不调用 `deleteUrl`、`deleteRange`、`deleteAll` 或 `addUrl`。次数只与用户自己的收藏做匹配，只显示在界面上，不上传、不存到服务器、不用于广告或画像。

没有更窄的权限，因为「打开次数」只存在于历史权限之后。

### `idle` · `08-permission-idle.txt`

用来在用户走开时停止计时。`chrome.idle.onStateChanged` 会报「idle」与「locked」，机器无人值守时计时器暂停，这样一夜挂着没关的页面不会被记成几个小时的阅读。

只读状态。从不检查活动类型，不存也不发任何关于用户的信息，阈值设 300 秒，避免短暂停顿被误判成空档。

没有更窄的 API：平台里没有别的东西能告诉你这台机器无人使用。

## 数据使用说明 · `10-data-usage-text.txt`（当前表单里没有这个框）

表单只有九项勾选，没有自由文本。**没有这一栏就整段跳过。** 下面的文字只在表单确实出现「理由 / Justification」框时才用，内容与隐私政策页 §1 的说法一致。

**网络记录**：扩展读取用户自己的浏览历史，用来数清每个「已经收藏过的」页面被打开过几次，好让收藏列表能排序、体检页能排名。计数在浏览器内存里完成，不保留访问列表的副本。不上传，没有服务器，没有账号，没有统计上报。

**用户活动**：空闲状态只有一个用途 —— 用户离开或锁屏时暂停本地计时器，避免无人值守的时间被算成浏览时间。不记录击键、点击、指针位置或滚屏。状态当场判断完就丢，不存储、不记日志、不传输。

## 远程代码 · `14-remote-code.txt`

**先点「不，我并未使用远程代码」。** 点完通常就不用填理由了。若后台仍然要文字，粘这段：

否。安装包里带着全部 JavaScript，运行时不下载也不求值任何代码。

构建产物里没有 `eval()`、没有 `new Function()`、没有指向远程地址的动态 `import`，也没有远程 script 或 wasm 文件。manifest 没有覆盖 `content_security_policy`，所以 MV3 默认的 `script-src 'self'` 原样生效。扩展完全不发网络请求。

> 这段是可核验的，不是话术：`dist/chrome-mv3` 里 grep 过 `eval(`、`new Function` 与 `http(s)://`，命中的只有 SVG/MathML 命名空间字符串和 GitHub 链接，没有一处会被加载。

## 数据使用

这个表单**只有勾选框，没有说明文本框** —— 九项分类勾完就直接到三条确认，再下面是隐私政策网址。所以没有地方写「我们只在本地处理」这种话，**解释的责任全部落在隐私政策页上**。`docs/privacy.html` §1 已经补了一段专门讲浏览历史：只读、只用于计数、不保存访问列表。

**勾这两项**

- [x] **网络记录** —— 页面原文：「用户访问过的网页及相关数据（例如网页标题和访问时间）的列表」。收藏列表排序和收藏体检都要数访问次数，必须勾。
- [x] **用户活动** —— `idle` 权限属于这一类。

**其余七项全部不勾**

- [ ] 个人身份信息　- [ ] 健康信息　- [ ] 财务和付款信息　- [ ] 身份验证信息
- [ ] 个人通讯　- [ ] 位置　- [ ] 网站内容

> ⚠️ 中文界面里**没有**一块叫「Web history」的勾选框，它是「**网络记录**」。按英文名去找会以为漏了一整类。
>
> ⚠️ 「用户活动」的帮助文字列的是「网络监控、点击、鼠标指针位置、滚屏或击键操作记录」—— 这些我们一样都不做，只读一个「在场/离开」的状态。但 `idle` 权限确实归在这一类，不勾就是申报不实，审核会拿 manifest 对。
>
> 为什么不勾「网站内容」：manifest 里没有 `host_permissions`、没有 `content_scripts`，扩展根本不读页面 DOM、不读剪贴板、不读表单。勾了反而与事实不符。
