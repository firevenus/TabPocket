# TabPocket v0.5.2 · 收藏体检排序修复

> 本地测试版，未推送 GitHub。

## 修了什么

**「按访问频次排序」失效的根因：`chrome.history.getVisits()` 被传错了参数。**

这个 API 的 `details` 只接受 `url` 一个字段。旧代码多传了 `startTime` / `endTime`，Chrome 的参数校验判定为 `Unexpected property` 直接抛错，而外层 `catch {}` 把它吞掉了。结果是：**每条书签都拿到 0 次访问**，排序退化成书签原始顺序，看起来就是"没按频次排"。

修法：`getVisits({ url })` 拿全部访问记录，再在本地用 `visitTime` 过滤区间。区间统计依然准确，且不再依赖浏览器是否支持额外参数。

## 一并处理的连带问题

1. **旧缓存作废**：上一版把"全 0"的结果存进了 `storage.local`，直接打开会先显示坏数据。现在结果带 `schema` 版本号，旧缓存自动丢弃并重新扫描。
2. **诊断卡片**：区间内访问次数全是 0 时，页面顶部列出四项——历史接口是否可用 / 历史里有没有数据 / 最新一条历史记录时间 / 逐条统计报错。不再需要猜。
3. **收藏列表可按频次排序**：弹窗「收藏」页新增排序切换 **最近收藏 / 按访问频次**（近一年），选频次时每条会显示"N 次"。之前「整理浏览器收藏」导进来的条目只有收藏时间顺序。
4. **域名视角排序稳定**：访问次数相同时按最近访问时间兜底，避免同分条目随机跳动。

## 验证

- `npm run compile` 通过
- `npm run build` 通过（audit 页 9.8 kB，弹窗主包 14.8 kB）
- `scripts/selftest-audit.mjs` **23 项断言全过**。旧版 mock 无条件接受任意参数，才漏掉了这个 bug；现在 mock 严格模拟 Chrome 的参数校验——多传一个字段就抛 `Unexpected property`，同类问题以后跑自测就会炸。

## 怎么更新

1. 建议先在「收藏 → 导出备份」存一份 JSON
2. 把 `release\TabPocket-v0.5.2\` 里的文件**覆盖**到你当前加载的那个目录
3. `edge://extensions` → 该扩展卡片 → **重新加载**

权限没有变化，不会弹新授权。
