# TabPocket v0.5.1 — 统计"空白"修复

## 为什么之前统计是空的

排查结论（查了 Edge 的实际磁盘数据，不是猜）：

- 扩展的 `IndexedDB / tabpocket-stats` **只建了表结构，一条记录都没有**
- `storage.session` 里从来没有过 `trackState` → 计时状态一次都没写入
- `Preferences` 里也没有 `tabpocket-heartbeat` 这个 alarm → 心跳一次都没建成

说明**后台计时那段代码根本没执行过**。原因是：扩展是从 `dist/chrome-mv3` 加载的，
而我在两次重新构建时把整个 `dist` 目录改名移走了（构建脚本为了绕开被占用文件的处理），
正在运行的扩展后台直接失联，之后所有事件都没人接。

用 mock 浏览器 API 复跑了一遍 `background.ts`（`scripts/selftest-background.mjs`，20 项断言全过），
确认计时逻辑本身没问题，是运行环境被我再构建时弄断了。

## 本次改动

### 1. 统计页新增「后台状态」诊断卡片

不用再猜，直接看五件事：

| 指标 | 含义 |
|---|---|
| 后台服务 | 后台 Service Worker 是否响应（未响应 = 需要重新加载扩展） |
| 自动结算心跳 | alarm 是否注册、周期多少 |
| 正在计时 | 当前正在计时的域名和已计时的时长 |
| 库里记录 | IndexedDB 里有多少条聚合记录 |
| 最近一次写入 | 距今多久 |

旁边有 **「立即结算一次」** 按钮（走新增的 `SETTLE_NOW` 消息），不用等 60 秒心跳就能验证链路是否通。

### 2. 判定"有数据"的逻辑修正

原来页面只按 `累计时长 > 0` 判空，导致「有访问次数、但时长还没累计起来」时被当成没有数据。
现在时长或访问次数任一有值就显示图表，KPI 也新增了「访问次数」。

### 3. 空闲判定放宽：60 秒 → 5 分钟

原来只要 60 秒没动鼠标就算"离开"，看长文 / 看视频整段都不计时。
现在改成 5 分钟，并同步调用 `idle.setDetectionInterval(300)` 让事件和查询用同一个阈值。

### 4. 弹窗统计页增加后台失联警告

后台没响应时，弹窗顶部直接红条提示去重新加载扩展。

## 更新方式（重要）

1. `edge://extensions`
2. 找到 TabPocket → 点 **「重新加载」**（**必须点**，文件已经换过了）
3. 打开统计页，先看「后台状态」卡片：五项都应是正常/已注册/有记录
4. 正常上网 2-3 分钟，或直接点「立即结算一次」

> 以后我每次重新构建扩展，你都需要点一次「重新加载」，否则后台会停在旧文件上。
> 现在诊断卡片会直接把这个状态标红，不用再靠猜。
